================================================================================
  SECTION 8 — JAVASCRIPT BEHAVIOUR (assets/js/script.js)
================================================================================

The script is 122 lines, uses 'use strict' mode throughout.
All DOM manipulation is vanilla JavaScript — no frameworks or libraries.

--- FEATURE 1: Sidebar Toggle (mobile) ---
  Selector: [data-sidebar]
  Button:   [data-sidebar-btn]
  Behaviour: Clicking the "Show Contacts" button on mobile toggles the
             "active" class on the sidebar element, expanding/collapsing
             the contacts section. The sidebar has a CSS max-height
             transition (0.5s ease-in-out) to animate the expansion.

--- FEATURE 2: Portfolio Filter (dropdown, mobile) ---
  Selector for dropdown:  [data-select]
  Selector for items:     [data-select-item]
  Selector for value:     [data-selecct-value]  (note: typo in attribute name,
                          spelled "selecct" with double 'c' — must match HTML)
  Behaviour:
    Clicking the dropdown button toggles the dropdown open/closed.
    Clicking any item inside the dropdown:
      1. Updates the displayed value text
      2. Closes the dropdown
      3. Calls filterFunc() with the selected category

--- FEATURE 3: Portfolio Filter (tab buttons, desktop >= 768px) ---
  Selector: [data-filter-btn]
  Behaviour:
    Clicking a filter tab:
      1. Gets the button's inner text (lowercased)
      2. Updates the select value display text
      3. Calls filterFunc()
      4. Removes "active" class from the previously active button
      5. Adds "active" class to the clicked button
  Note: Both the dropdown (mobile) and tab buttons (desktop) call the
        same filterFunc(), keeping behaviour consistent.

--- filterFunc(selectedValue) ---
  Iterates over all [data-filter-item] elements.
  If selectedValue === "all"  → adds class "active" to every item
  If selectedValue matches element's data-category attribute → adds "active"
  Otherwise → removes "active"
  Items without class "active" are hidden via CSS (display: none).

--- FEATURE 4: Contact Form Validation ---
  Selectors:
    Form:        [data-form]
    Inputs:      [data-form-input]  (all input and textarea fields)
    Submit btn:  [data-form-btn]
  Behaviour:
    Every input event on any form field checks form.checkValidity().
    If valid  → removes "disabled" attribute from submit button
    If invalid → sets "disabled" attribute on submit button
  The submit button starts as disabled="disabled" in HTML.

--- FEATURE 5: Tab Navigation (SPA routing) ---
  Selectors:
    Nav links: [data-nav-link]
    Pages:     [data-page]
  Behaviour:
    On clicking any nav link, iterates over all pages.
    Compares link's innerHTML (lowercased) to page's data-page attribute.
    Matching page/link pair → adds "active" class → scrolls to top
    Non-matching pages/links → removes "active" class
  The About article has class="about active" by default in HTML (shown on load).

  SECTION 14 — NOTABLE OBSERVATIONS & TECHNICAL NOTES
================================================================================

1. The portfolio is a single HTML file with no backend. The contact form has
   no server-side handler — clicking "Send Message" (when enabled) submits to
   "#" and does nothing. Backend integration (e.g. EmailJS, Formspree) would
   be required to make it functional.

2. The project links in the Portfolio section all point to "#" — no live
   project pages or external URLs are wired up yet.

3. There is a typo in the HTML attribute name on line 25: "data-selecct-value"
   (double 'c'). This is intentional/consistent — the JS also references it as
   "data-selecct-value" so the functionality works correctly despite the typo.

4. The site was built on the "vCard" template by @codewithsadee (MIT licensed).
   All personal content (bio, experience, skills, projects) has been replaced
   with Anis Bouchema's real information. Some template artifacts remain:
   - index.txt contains the original template's placeholder content
   - blog-*.jpg images remain in assets/images/ though the Blog tab was removed
   - avatar-1.png through avatar-4.png (template testimonial avatars) remain
   - project-7.png, project-8.jpg, project-9.png are in images/ but not used
   - logo-1 through logo-6 color PNGs are in images/ (template client logos)

5. The "La Diperie — Business Operator (High Park Launch)" role lists a start
   date of Jun 2022, which is chronologically after "La Diperie — Business
   Operator" (Sep 2021) but appears third in the list. The ordering in the HTML
   is: current Oakville role → historical GM role → High Park launch → other roles.

6. myavatar.png is 1.27 MB — considerably large for a profile photo displayed
   at 80px (mobile) to 150px (desktop). Compression would improve load time.

7. The file "LaDiperie_Resource_Scheduler Exaample.xlsx" has a typo in the
   filename (double 'a' in "Exaample"). The corresponding desktop.ini in the
   projects folder is a Windows system artifact with no content value.

8. The CSS contains rules for .testimonials, .modal-container, .clients, and
   .blog-posts that are no longer used in the live HTML (those sections were
   removed from the template during customization), but the CSS rules remain.

9. CSS font-weight on .service-item-text uses --fw-3 (line 554) which is an
   undefined custom property — the correct variable is --fw-300. This is a
   minor bug that causes the font-weight to fall back to the browser default.

10. The site has no meta description, Open Graph tags, Twitter Card tags, or
    structured data (JSON-LD). Adding these would improve SEO and social sharing.
